# УВМ: ассемблер и интерпретатор учебной виртуальной машины

Практическая работа № 3 по дисциплине «Конфигурационное управление»
(РТУ МИРЭА, ИКБО-32-25), вариант 6. Язык реализации: Python 3.9+
(сторонние библиотеки не нужны).

## 1. Общее описание

Проект состоит из двух консольных программ:

* **ассемблер** переводит текст программы на «алгебраическом» языке
  ассемблера в двоичный файл с командами УВМ;
* **интерпретатор** выполняет двоичную программу и сохраняет дамп памяти
  в JSON (появится на этапе 3).

Состояние проекта: **этап 1** — разбор языка ассемблера и перевод в
промежуточное представление.

Структура репозитория:

```
src/uvm/      исходный код (spec, parser, assembler)
tests/        модульные тесты (unittest)
programs/     примеры программ на языке ассемблера
tools/        проверка оформления кода (check_style.py)
run.sh, run.bat, Makefile   запуск и тесты
```

## 2. Спецификация УВМ (вариант 6)

Команда хранится как целое число в порядке байт little-endian, поля
нумеруются от младшего бита. Поле A всегда содержит код операции.

| Команда | A (биты) | B | C | D | E | Размер |
|---------|----------|---|---|---|---|--------|
| Загрузка константы | 1 (0–3) | адрес регистра (4–10) | константа (11–33) | — | — | 5 байт |
| Чтение из памяти | 13 (0–3) | адрес регистра (4–10) | адрес регистра (11–17) | — | — | 3 байта |
| Запись в память | 0 (0–3) | адрес регистра (4–10) | адрес регистра (11–17) | — | — | 3 байта |
| sqrt() | 12 (0–3) | смещение (4–15) | адрес регистра (16–22) | адрес регистра (23–29) | смещение (30–41) | 6 байт |

Регистров 128 (адрес — 7 бит), константа — 23 бита (0…8388607),
смещение — 12 бит (0…4095).

## 3. Язык ассемблера

Один оператор на строку. `rN` — регистр с номером N, `[...]` — ячейка
памяти по адресу.

| Оператор | Команда | Поля |
|----------|---------|------|
| `rB = C` | загрузка константы: регистр B получает C | A=1, B, C |
| `rB = [rC]` | чтение: регистр B получает значение памяти по адресу из регистра C | A=13, B, C |
| `[rB] = rC` | запись: в память по адресу из регистра B кладётся регистр C | A=0, B, C |
| `[rC + E] = sqrt([rD + B])` | корень из значения памяти по адресу «регистр D + смещение B», результат в память по адресу «регистр C + смещение E» | A=12, B, C, D, E |

Правила записи:

* смещение `+ N` можно не писать (оно равно 0): `[r5] = sqrt([r6])`;
* числа — десятичные или шестнадцатеричные (`0x1F`), допускается `_`
  (`1_000`); отрицательные числа не поддерживаются;
* комментарий начинается с `#` или `;` и идёт до конца строки;
* регистр букв и пробелы вокруг знаков значения не имеют;
* значения проверяются на помещение в поле, при ошибке выводится номер
  строки.

Пример (`programs/spec_tests.asm`) — все тесты из спецификации:

```
r62 = 266
r6 = [r30]
[r88] = r68
[r98 + 804] = sqrt([r23 + 507])
```

## 4. Запуск ассемблера

```
run.sh asm ИСХОДНИК ДВОИЧНЫЙ_ФАЙЛ [--test]      # Linux / macOS
run.bat asm ИСХОДНИК ДВОИЧНЫЙ_ФАЙЛ [--test]     # Windows
```

| Аргумент | Описание |
|----------|----------|
| `ИСХОДНИК` | путь к файлу с текстом программы |
| `ДВОИЧНЫЙ_ФАЙЛ` | путь к двоичному файлу-результату |
| `--test` | режим тестирования: вывести поля и значения каждой команды |

Без скриптов: `PYTHONPATH=src python3 -m uvm.assembler ...`
(в PowerShell: `$env:PYTHONPATH="src"; python -m uvm.assembler ...`).

Пример режима тестирования:

```
$ ./run.sh asm programs/spec_tests.asm out/spec.bin --test
A=1, B=62, C=266
A=13, B=6, C=30
A=0, B=88, C=68
A=12, B=507, C=98, D=23, E=804
Разобрано команд: 4
```

## 5. Тесты и проверка оформления

```
make test        # или: PYTHONPATH=src python3 -m unittest discover -s tests -v
make check       # или: python3 tools/check_style.py src tests tools
```

Тесты этапа 1 проверяют, что ассемблер даёт те же поля и значения, что
приведены в спецификации УВМ, а также разбор вариантов записи и ошибки.
