# УВМ: ассемблер и интерпретатор учебной виртуальной машины

Практическая работа № 3 по дисциплине «Конфигурационное управление»
(РТУ МИРЭА, ИКБО-32-25), вариант 6. Язык реализации: Python 3.9+
(сторонние библиотеки не нужны).

## 1. Общее описание

Проект состоит из двух консольных программ:

* **ассемблер** переводит текст программы на «алгебраическом» языке
  ассемблера в двоичный файл с командами УВМ;
* **интерпретатор** выполняет двоичную программу и сохраняет дамп памяти
  в JSON.

Состояние проекта: **этап 5** — ассемблер, интерпретатор со всеми
четырьмя командами и решение тестовой задачи (`sqrt()` над вектором длины 6).

Структура репозитория:

```
src/uvm/      исходный код (spec, parser, codec, assembler, machine, interpreter)
tests/        модульные тесты (unittest)
programs/     примеры программ на языке ассемблера
tools/        проверка оформления кода (check_style.py)
run.sh, run.bat, Makefile   запуск и тесты
```

## 2. Спецификация УВМ (вариант 6)

Команда хранится как целое число в порядке байт little-endian, поля
нумеруются от младшего бита. Поле A всегда содержит код операции.

| Команда | A (биты) | B | C | D | E | Размер |
|---------|----------|---|---|---|---|--------|
| Загрузка константы | 1 (0–3) | адрес регистра (4–10) | константа (11–33) | — | — | 5 байт |
| Чтение из памяти | 13 (0–3) | адрес регистра (4–10) | адрес регистра (11–17) | — | — | 3 байта |
| Запись в память | 0 (0–3) | адрес регистра (4–10) | адрес регистра (11–17) | — | — | 3 байта |
| sqrt() | 12 (0–3) | смещение (4–15) | адрес регистра (16–22) | адрес регистра (23–29) | смещение (30–41) | 6 байт |

Регистров 128 (адрес — 7 бит), константа — 23 бита (0…8388607),
смещение — 12 бит (0…4095).

## 3. Язык ассемблера

Один оператор на строку. `rN` — регистр с номером N, `[...]` — ячейка
памяти по адресу.

| Оператор | Команда | Поля |
|----------|---------|------|
| `rB = C` | загрузка константы: регистр B получает C | A=1, B, C |
| `rB = [rC]` | чтение: регистр B получает значение памяти по адресу из регистра C | A=13, B, C |
| `[rB] = rC` | запись: в память по адресу из регистра B кладётся регистр C | A=0, B, C |
| `[rC + E] = sqrt([rD + B])` | корень из значения памяти по адресу «регистр D + смещение B», результат в память по адресу «регистр C + смещение E» | A=12, B, C, D, E |

Правила записи:

* смещение `+ N` можно не писать (оно равно 0): `[r5] = sqrt([r6])`;
* числа — десятичные или шестнадцатеричные (`0x1F`), допускается `_`
  (`1_000`); отрицательные числа не поддерживаются;
* комментарий начинается с `#` или `;` и идёт до конца строки;
* регистр букв и пробелы вокруг знаков значения не имеют;
* значения проверяются на помещение в поле, при ошибке выводится номер
  строки.

Пример (`programs/spec_tests.asm`) — все тесты из спецификации:

```
r62 = 266
r6 = [r30]
[r88] = r68
[r98 + 804] = sqrt([r23 + 507])
```

## 4. Запуск ассемблера

```
run.sh asm ИСХОДНИК ДВОИЧНЫЙ_ФАЙЛ [--test]      # Linux / macOS
run.bat asm ИСХОДНИК ДВОИЧНЫЙ_ФАЙЛ [--test]     # Windows
```

| Аргумент | Описание |
|----------|----------|
| `ИСХОДНИК` | путь к файлу с текстом программы |
| `ДВОИЧНЫЙ_ФАЙЛ` | путь к двоичному файлу-результату |
| `--test` | режим тестирования: вывести поля и байты каждой команды |

После работы ассемблер выводит число ассемблированных команд. Двоичный
файл — это конкатенация команд; каждая команда записывается в порядке
байт little-endian и имеет размер 3, 5 или 6 байт (см. таблицу выше).

Без скриптов: `PYTHONPATH=src python3 -m uvm.assembler ...`
(в PowerShell: `$env:PYTHONPATH="src"; python -m uvm.assembler ...`).

Пример режима тестирования (для каждой команды печатаются поля и байты,
как в тестах спецификации):

```
$ ./run.sh asm programs/spec_tests.asm out/spec.bin --test
A=1, B=62, C=266
0xE1, 0x53, 0x08, 0x00, 0x00
A=13, B=6, C=30
0x6D, 0xF0, 0x00
A=0, B=88, C=68
0x80, 0x25, 0x02
A=12, B=507, C=98, D=23, E=804
0xBC, 0x1F, 0xE2, 0x0B, 0xC9, 0x00
Ассемблировано команд: 4
```

Файл `programs/spec_tests.asm` транслируется ровно в четыре тестовые
последовательности из спецификации.

## 5. Интерпретатор

```
run.sh vm ПРОГРАММА ДАМП НАЧАЛО:КОНЕЦ        # Linux / macOS
run.bat vm ПРОГРАММА ДАМП НАЧАЛО:КОНЕЦ       # Windows
```

| Аргумент | Описание |
|----------|----------|
| `ПРОГРАММА` | двоичный файл, полученный ассемблером |
| `ДАМП` | путь к JSON-файлу, куда сохраняется дамп памяти |
| `НАЧАЛО:КОНЕЦ` | диапазон адресов дампа (`КОНЕЦ` не включается), например `200:205` |

**Модель машины.** Память — единый массив из 65536 ячеек для команд и
данных. Программа загружается с адреса 0, по одному байту в ячейку;
данные нужно размещать за концом программы (иначе они затрут код). Ячейка
данных хранит целое число. Регистров 128, в начале работы память и
регистры равны нулю. Основной цикл: прочитать команду из памяти по
счётчику команд, перевести её в промежуточное представление
(`codec.decode`), выполнить, сдвинуть счётчик на размер команды.
Работа заканчивается, когда счётчик выходит за конец программы.

**Выполнение команд.**

| Оператор | Действие |
|----------|----------|
| `rB = C` | `регистр[B] = C` |
| `rB = [rC]` | `регистр[B] = память[регистр[C]]` |
| `[rB] = rC` | `память[регистр[B]] = регистр[C]` |
| `[rC + E] = sqrt([rD + B])` | `память[регистр[C] + E] = isqrt(память[регистр[D] + B])` |

Команда `sqrt()` (операция АЛУ) работает только с памятью и не меняет
регистры. Ячейки хранят целые числа, поэтому берётся **целый корень с
округлением вниз** (`math.isqrt`): `sqrt(144) = 12`, `sqrt(2) = 1`,
`sqrt(0) = 0`. Исходное значение и результат могут находиться в одной
ячейке (`[r1] = sqrt([r1])` заменяет число его корнем).

Ошибки (адрес вне памяти, неизвестный код операции, неверный диапазон
дампа, затёртый код) выводятся сообщением, код завершения 1.

**Формат дампа (JSON).** `start` и `end` — границы диапазона, `memory` —
значения ячеек подряд:

```
{"start": 300, "end": 305, "memory": [101, 202, 303, 404, 505]}
```

**Пример: копирование массива.** Программа `programs/copy_array.asm`
заполняет массив из пяти элементов по адресам 200–204 и копирует его на
адреса 300–304 (в УВМ нет циклов, поэтому код записан последовательно):

```
$ ./run.sh asm programs/copy_array.asm out/copy.bin
Ассемблировано команд: 35
$ ./run.sh vm out/copy.bin out/dump.json 300:305
Выполнено команд: 35
Дамп памяти [300:305) сохранён в out/dump.json
$ cat out/dump.json
{"start": 300, "end": 305, "memory": [101, 202, 303, 404, 505]}
```

**Пример: sqrt.** Программа `programs/sqrt_demo.asm` записывает числа
144, 2025, 2, 0 и 1000000 по адресам 1000–1004 и вычисляет их корни в
ячейки 1100–1104:

```
$ ./run.sh asm programs/sqrt_demo.asm out/demo.bin
Ассемблировано команд: 22
$ ./run.sh vm out/demo.bin out/dump.json 1100:1105
Выполнено команд: 22
Дамп памяти [1100:1105) сохранён в out/dump.json
$ cat out/dump.json
{"start": 1100, "end": 1105, "memory": [12, 45, 1, 0, 1000]}
```

## 6. Тестовая задача: sqrt над вектором длины 6

Условие: выполнить поэлементно `sqrt()` над вектором из шести чисел, а
результат записать в исходный вектор. Вектор лежит по адресам 1000–1005.
Программа сначала заполняет его (в УВМ нет другого способа задать данные),
затем одним регистром `r0 = 1000` и смещениями вычисляет корни на месте:

```
r0 = 1000
[r0 + 0] = sqrt([r0 + 0])
[r0 + 1] = sqrt([r0 + 1])
...
[r0 + 5] = sqrt([r0 + 5])
```

Смещение команды `sqrt` позволяет обойтись одним регистром для всего
вектора. Готовые программы в папке `programs/` (запуск для каждой:
`run.sh asm programs/ИМЯ.asm out/ИМЯ.bin`, затем
`run.sh vm out/ИМЯ.bin out/ИМЯ.json 1000:1006`):

| Программа | Исходный вектор | Дамп 1000:1006 после выполнения |
|-----------|-----------------|---------------------------------|
| `sqrt_vector.asm` (тестовая задача) | 1, 4, 9, 16, 25, 36 | `[1, 2, 3, 4, 5, 6]` |
| `example_squares.asm` (точные квадраты) | 49, 64, 81, 100, 121, 144 | `[7, 8, 9, 10, 11, 12]` |
| `example_arbitrary.asm` (произвольные числа) | 2, 10, 50, 99, 1000, 8388607 | `[1, 3, 7, 9, 31, 2896]` |
| `example_edges.asm` (граничные значения) | 0, 1, 3, 4, 65536, 1000000 | `[0, 1, 1, 2, 256, 1000]` |

Пример запуска:

```
$ ./run.sh asm programs/example_arbitrary.asm out/arb.bin
Ассемблировано команд: 25
$ ./run.sh vm out/arb.bin out/arb.json 1000:1006
Выполнено команд: 25
Дамп памяти [1000:1006) сохранён в out/arb.json
$ cat out/arb.json
{"start": 1000, "end": 1006, "memory": [1, 3, 7, 9, 31, 2896]}
```

Корни не-квадратов округляются вниз: `sqrt(2) = 1`, `sqrt(99) = 9`,
`sqrt(8388607) = 2896`. Тесты (`tests/test_programs.py`) проверяют вектор
до и после выполнения и свойство `r*r <= x < (r+1)*(r+1)` для каждого
результата.

Все примеры разом запускает `make demo` (Linux/macOS).

## 7. Тесты и проверка оформления

```
make test        # или: PYTHONPATH=src python3 -m unittest discover -s tests -v
make check       # или: python3 tools/check_style.py src tests tools
```

Тесты проверяют, что ассемблер даёт те же поля, значения и байты, что
приведены в спецификации УВМ, а также разбор вариантов записи, границы
полей, содержимое двоичного файла, обратный перевод байтов в команды,
работу памяти и регистров, команду sqrt (точные квадраты, округление
вниз, смещения, границы), дамп JSON, программы копирования массива и
sqrt-демо, вектор длины 6 с тремя примерами, обработку ошибок.
